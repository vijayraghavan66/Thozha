# Browser session API v1 (proposed; not implemented)

This contract is a design target for the Web Workspace, not a currently available route. The Android paired-device bearer token is never accepted by or exposed to browser code.

## Session principal

The server resolves an opaque browser session to a server-side `WebPrincipal` containing an authenticated owner ID, a session ID, and expiry. Request bodies cannot select or override the owner ID. Conversation, memory, automation, task, device, and approval routes must authorize through this principal before reading or changing state.

## Proposed routes

| Method and path | Purpose | Status |
|---|---|---|
| `POST /v1/web/session/login` | Verify a locally configured owner credential, rotate any existing session, create a server-side session, and set an opaque cookie. | Proposed |
| `GET /v1/web/session` | Return authenticated owner/session metadata and a CSRF token; no device token or secret. | Proposed |
| `POST /v1/web/session/logout` | Revoke the server-side session and expire the cookie. | Proposed |

No implementation or browser client exists for these routes yet. Do not call them from the MagicPath frontend until the server implementation and integration tests land.

## Cookie and request protections

- Cookie is opaque, `HttpOnly`, `SameSite=Strict`, scoped to `/v1/web`, and `Secure` on HTTPS. Insecure cookies are only permitted for an explicitly enabled loopback development mode.
- Login credentials are configured on the Mac outside Git; no default password is created. If auth is not configured, login fails closed.
- State-changing requests require a session-bound CSRF token in a custom header, a same-origin `Origin` check, and JSON content type. CORS uses exact configured origins only; no wildcard or credentialed cross-origin access.
- Sessions rotate at login, expire server-side, and can be revoked at logout. Login attempts are rate-limited. Session cookies and CSRF values are never logged.
- This browser session is separate from Android pairing and does not grant privileged Mac tools by itself. Supervisor approval and sandbox policy remain authoritative.

## Shared backend interface

The Web API modules will depend on `require_web_session(request) -> WebPrincipal`. This interface lives in the backend package; route modules must not parse cookies or accept owner/device identity from request payloads themselves.
