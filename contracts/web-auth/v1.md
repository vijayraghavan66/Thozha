# Thozha Web session and conversation API v1

Status: implemented in the OpenJarvis source tree and mounted by `create_app()`. Browser authentication is disabled unless the complete owner configuration is provided outside Git. No production browser credential or deployment has been configured or tested.

The Android paired-device bearer token is never accepted or exposed by this API. The browser session is a separate identity and does not grant privileged Mac tools.

## Session principal

The server resolves an opaque browser session to `WebPrincipal(user_id, session_id, expires_at)`, where `expires_at` is Unix epoch seconds. Request bodies cannot select or override the owner ID. Conversation data is always scoped to the authenticated principal.

## Implemented routes

| Method and path | Behavior |
|---|---|
| `POST /v1/web/session/login` | Verify the locally configured owner credential, revoke any prior session cookie, create a server-side session, and return an opaque cookie plus CSRF token. Returns 503 when auth is not configured. |
| `GET /v1/web/session` | Return the current owner and expiry with a CSRF token; no device token or secret. |
| `POST /v1/web/session/logout` | Revoke the server-side session and expire both cookies. |
| `POST /v1/web/conversations` | Create an owner-scoped conversation. |
| `GET /v1/web/conversations` | List the owner's non-archived conversations (or include archived when requested). |
| `GET /v1/web/conversations/{conversation_id}` | Read messages and persisted lifecycle events for an owned conversation. |
| `POST /v1/web/conversations/{conversation_id}/archive` | Archive an owned conversation. |
| `DELETE /v1/web/conversations/{conversation_id}` | Delete an owned conversation and its messages/events. |
| `POST /v1/web/conversations/{conversation_id}/messages` | Persist and accept a user message with a required `Idempotency-Key`; run the configured engine with tools disabled; return HTTP 202 and a response ID. |
| `POST /v1/web/conversations/{conversation_id}/messages/stream` | Authenticated SSE using the engine's `stream()` method with tools disabled. Emits deltas when the selected engine yields incrementally; reports `mode=buffered` for Codex SDK, which yields only after full generation. |
| `POST /v1/web/conversations/{conversation_id}/messages/{response_id}/cancel` | Request cancellation or cancel queued work. |
| `POST /v1/web/memory` | Persist a browser-owner-scoped memory with idempotency and per-owner size/count limits. |
| `GET /v1/web/memory` | List only this browser owner's memories. |
| `GET /v1/web/memory/search?q=...` | Deterministic case-insensitive substring search; not semantic/embedding retrieval. |
| `GET /v1/web/memory/{memory_id}` / `DELETE ...` | Read or delete only an owned memory item. |
| `POST /v1/web/tasks` | Create an async Link supervisor task with an idempotency key and an explicitly mapped active paired device. Existing Link scope validation and runner apply. |
| `GET /v1/web/tasks`, `GET /v1/web/tasks/{task_id}` | Read tasks only for mapped device owners. |
| `GET /v1/web/tasks/{task_id}/events` | Read sanitized, paginated durable events. |
| `GET /v1/web/tasks/{task_id}/events/stream` | Reconnectable SSE over persisted task events; uses `Last-Event-ID`, a bounded stream count, and device-map rechecks. This is progress streaming, not model-token streaming. |
| `POST /v1/web/tasks/{task_id}/cancel` | Cancel an owned Link task using the original supervisor cancellation boundary. |
| `GET /v1/web/approvals/pending`, `GET /v1/web/approvals/{approval_id}` | Review pending exact-operation approvals only for mapped task owners. |
| `POST /v1/web/approvals/{approval_id}/decision` | Approve/reject with the exact operation digest, expiry, nonce/replay, single-use dispatch-claim, and execution path shared with Android. |
| `GET /v1/web/tasks/{task_id}/artifacts` / `.../{artifact_id}/download` | Access completed development artifacts only for the mapped task owner; download verifies archive integrity and returns SHA-256 metadata. |
| `GET /v1/web/devices`, `GET /v1/web/devices/{device_id}` | List safe metadata for explicitly mapped active devices. |
| `POST /v1/web/devices/{device_id}/revoke` | Explicit confirm-gated revocation and FCM cleanup; this API cannot pair/enroll a device. |
| `GET /v1/web/automations/capabilities` | Report scheduler availability and unavailable operations. |
| `POST /v1/web/automations`, `GET /v1/web/automations`, `GET /v1/web/automations/{id}` | Owner-scoped schedule creation/list/detail. |
| `GET /v1/web/automations/{id}/history` | Durable occurrence history with current supervisor state/result. |
| `PATCH /v1/web/automations/{id}` | Update an owned schedule. |
| `POST /v1/web/automations/{id}/enable`, `/disable`, `/pause`, `/trigger`; `DELETE /v1/web/automations/{id}` | Lifecycle and manual run controls; trigger requires idempotency. |

Conversation GET returns persisted user/assistant message states and event history. The ordinary message endpoint uses `generate()` and returns a completed response when it finishes. The separate SSE endpoint uses the configured engine's `stream()` method; engines with native streaming emit deltas. `CodexSDKEngine.stream()` currently wraps a blocking full `generate()` and is reported as `buffered`, so it does not reduce first-token latency. `tools=[]` is explicit. Conversation generation is not supervisor task execution and cannot invoke Mac tools.

## Recovery and cancellation limits

The conversation database is persistent and owner-scoped. At first authenticated request after process creation, queued responses may be scheduled; uncertain `RUNNING` responses are terminally marked `process_interrupted` and are not replayed. The current worker ownership model requires one API process per conversation database. Cancellation prevents a late model result from being stored or returned, but Python cannot forcibly stop a blocking `engine.generate()` already running in a worker thread. These routes are for browser chat, not durable autonomous tasks.

## Browser-to-supervisor identity mapping

The single configured Web owner is bound to an explicit comma-separated allowlist in `THOZHA_WEB_ALLOWED_DEVICE_IDS`. The allowlist is read from server configuration, never from request data; each ID must identify a currently paired, unrevoked, unexpired companion. Missing or invalid mappings fail closed. A mapped device ID is not a device credential and is never returned as a bearer token. The API stores supervisor task ownership as the existing `device:<id>` actor and checks that owner on every task, event, approval, and artifact read. Revocation checks mapping membership only to retry cleanup; it never restores device access.

Web task approvals call the exact same shared supervisor decision function as the Android route. They do not create a second executor or capability path. The owner must inspect and approve/reject on the client; no approval is synthesized.

## Automation limits

Automation routes are enabled only when `THOZHA_WEB_AUTOMATION_ENABLED=1`, complete browser auth is configured, and the durable Link runner is active. They use a dedicated owner-only scheduler database and only `read_only` scope. Each occurrence is submitted as a normal supervisor Link task tied to the selected active device; it never calls `System.ask`, MCP, shell, or direct tools. Update/pause/delete only mutate the authenticated owner's Web schedule and preserve run history. Manual triggers create a new idempotent read-only Link task. Broader scopes and tool-capable schedules are unavailable.

## Cookie and request protections

- Session cookie: opaque, `HttpOnly`, `SameSite=Strict`, scoped to `/v1/web`, and `Secure` on HTTPS. Insecure cookies require an explicit loopback-development setting.
- Configuration is read from `THOZHA_WEB_OWNER_ID`, `THOZHA_WEB_PASSWORD_HASH`, and `THOZHA_WEB_ORIGIN`; the password hash is generated with the supported PBKDF2 helper. No default credential is created. Do not put values in source, app assets, or Git history.
- Session IDs are stored as SHA-256 digests. SQLite parent directories must be owner-only, and the database must be mode `0600`, otherwise startup fails closed.
- State-changing requests require session-bound `X-Thozha-CSRF`, exact same-origin `Origin`, and JSON content type. Wildcard credentialed CORS is not allowed.
- Login attempts are rate-limited in process memory. Multi-worker deployments require a shared edge/proxy limiter or shared rate-limit store before exposure.
- Logout, server-side expiry, and revocation invalidate sessions. Session and CSRF values are never logged.

## Not implemented / not mounted

- Browser notifications/history and semantic/embedding-backed Web memory are not implemented. Web memory search currently uses deterministic substring matching.
- Web automations are read-only only; development or tool-capable recurring schedules are not implemented.
- Web memory is separate from Android/OpenJarvis global memory: it has persistent owner-isolated records and substring search, not embeddings or semantic retrieval.
- A remote/Tailscale/public deployment is not configured or tested.

## Frontend integration rules

Use the typed contract and `require_web_session` dependency. Never put paired-device bearer tokens in browser storage, URLs, source maps, or JavaScript bundles. Preview fixtures must be visibly labeled and cannot be presented as live state. Authorization-sensitive actions remain unavailable until their actual backend route and supervisor boundary exist.
