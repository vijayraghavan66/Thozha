# Companion HTTP API v1

Status: source-derived contract for the current OpenJarvis supervisor and Android client. This is not a public Internet API. Routes run on the loopback Mac service or, when explicitly configured, a restricted TLS-pinned companion gateway.

Source revisions audited: Android integration/telegram-ui at 372a364; OpenJarvis source at 13ddffc5. The gateway task-submission body was aligned in 633a3085 and covered by tests/server/test_companion_gateway.py.

## Authentication and transport

- Device requests use Authorization: Bearer paired-device-token. Tokens are held by the native secure store and must not be placed in URLs, browser storage, logs, or Web mock data.
- The direct OpenJarvis API is loopback-only at port 8000. A companion gateway may proxy only its explicit route allowlist to that loopback service.
- Local Wi-Fi/Tailscale access requires the separate pinned HTTPS identity flow. Do not disable TLS verification or expose the raw API.
- The browser has no authorized token/session exchange in this contract. A Web client must not call these endpoints directly until a separate browser authentication design is approved.

## Task and status routes

| Method and path | State | Request / response |
|---|---|---|
| GET /v1/jarvis/system/info | Implemented; direct API and companion gateway allowlist | Read-only response contains online, battery_percent (nullable), charging (nullable), uptime_seconds, uptime, and checked_at. |
| GET /v1/jarvis/tasks?state=active&limit=100 | Implemented; direct API and gateway allowlist | state is active, completed, or all; limit is 1–100. Response is { tasks: [...] }. |
| GET /v1/jarvis/tasks/{task_id} | Implemented; direct API and gateway allowlist | Returns the task record with its persisted events list. |
| POST /v1/jarvis/link/tasks?mode=async | Implemented; direct API and gateway allowlist | JSON fields are exactly objective, capability_scope, idempotency_key, and requester_device_id. Gateway accepts capability_scope exactly ["read_only"] or ["assistant"]; development scope is not enabled through this gateway route. The authenticated paired device ID must equal requester_device_id. Objective limit on the gateway is 4096 UTF-8 bytes. The idempotency key is 16–128 URL-safe characters. Normal async acceptance returns HTTP 202 with task_id, state CREATED, summary, and idempotent_replay. A completed replay returns the stored result; duplicates do not create a second task. |
| GET /v1/jarvis/link/tasks/{idempotency_key} | Implemented; direct API and gateway allowlist | Returns task_id, state, summary, and terminal result_text/result_digest when completed. |
| GET /v1/jarvis/link/tasks/{idempotency_key}/events?after_seq=0&limit=100 | Implemented on direct loopback API; not in the companion gateway allowlist | Bounded, owner-authorized persisted event page. This is polling, not a WebSocket or push stream. |
| POST /v1/jarvis/link/tasks/{idempotency_key}/cancel | Implemented; direct API and gateway allowlist | Empty JSON object. Response reports actual task state and whether an already-started operation may have run. |

The direct async task route requires the configured Codex SDK engine and a running durable task runner; otherwise it returns a service error. The gateway has a 15-second upstream timeout, so clients should use async acceptance and poll task state rather than wait for model completion.

## Approval routes

| Method and path | State | Request / response |
|---|---|---|
| GET /v1/jarvis/approvals/pending?limit=100 | Implemented; direct API and gateway allowlist | Returns approvals, items, and count. Each approval contains the exact operation, target, canonical arguments, operation digest, task, status, and timestamps. |
| GET /v1/jarvis/approvals/{approval_id} | Implemented; direct API and gateway allowlist | Returns the selected approval payload. |
| POST /v1/jarvis/approvals/{approval_id}/decision | Implemented; direct API and gateway allowlist | Body accepts decision (approve/reject), task_id, expected_operation_digest, requester_device_id, idempotency_key, and optional bounded continuation_objective. Supervisor verifies task, digest, owner, expiry and single-use state. A successful decision is not evidence that the authorized action completed; read task state/events afterwards. |

The frontend must display the complete verified operation and target before enabling a decision. It must never fabricate a tap or infer approval from an API response.

## Artifacts

| Method and path | State | Notes |
|---|---|---|
| GET /v1/jarvis/tasks/{task_id}/artifacts | Implemented on direct loopback API; not in the companion gateway allowlist | Paired-device-owned completed development tasks only. Response contains archive metadata and per-file manifest. |
| GET /v1/jarvis/tasks/{task_id}/artifacts/{artifact_id}/download | Implemented on direct loopback API; not in the companion gateway allowlist | ZIP bytes; response includes X-Content-SHA256, ETag and content length. Android verifies size and SHA-256 before returning the archive. |

There is no approved browser-accessible artifact gateway endpoint in v1. Do not proxy these paths or create a browser credential flow in the Web mockup.

## Pairing and push registration

The native Android pairing flow uses the implementation in JarvisApi.kt and OpenJarvis supervisor routes. Gateway routes are invitation-scoped (/v1/jarvis/pair/{invitation_id}/complete, /status, /claim). Pairing is device management and is not a Web Workspace feature.

POST and DELETE /v1/jarvis/devices/fcm-token register or revoke the current paired device's FCM token through the direct API/gateway. Token registration is implemented. End-to-end push delivery is not certified by this contract.

## Not included

No browser login/session exchange, server-sent event route, WebSocket task-progress route, public remote-control endpoint, WebSocket audio service for the browser, or generic shell/MCP endpoint is defined by Companion HTTP API v1.

## Related OpenJarvis APIs outside Companion HTTP API v1

These routes exist in the general OpenJarvis server, but are not included in the restricted companion-gateway allowlist and are not a browser authorization contract:

| Method and path | State | Semantics / limitation |
|---|---|---|
| `POST /v1/chat/completions` | Implemented in the general OpenJarvis server | OpenAI-compatible JSON request. `stream=true` can return SSE for engines with streaming support. Server-agent/tool behavior depends on request and configured agent; do not expose this directly to a browser workspace. |
| `WebSocket /v1/chat/stream` | Implemented in the general OpenJarvis server | Authenticated WebSocket accepts a JSON `message` and optional `model`/`agent`, and emits `chunk`, `done`, or `error` messages. It is not device-bound through the companion gateway; a single engine may fall back to non-streaming generation. |
| `GET /v1/sessions` and `GET /v1/sessions/{session_id}` | Implemented in the general OpenJarvis server | Reads the server's SessionStore. This is not yet the paired-device conversation-history contract and is not exposed through the companion gateway. |
| `POST /v1/memory/store`, `POST /v1/memory/search`, `GET /v1/memory/stats`, `GET /v1/memory/config`, `POST /v1/memory/index` | Implemented in the general OpenJarvis server | Operates on the configured memory backend. When memory is unconfigured, store returns 503 and search reports an empty result. These routes are not companion-gateway allowlisted or bound to a per-device user memory profile. |

Therefore a Web client must not call these routes directly. Browser-safe authentication, per-user conversation history/memory, event streaming, and any gateway expansion are proposed contract work, not implemented Companion API behavior.
